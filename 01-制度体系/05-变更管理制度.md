# 变更管理制度

## 1. 目的

规范公司网络与系统变更管理流程，确保所有变更经过适当评估、审批、测试后上线，降低因变更导致的安全风险和业务中断。

## 2. 适用范围

适用于奇富科技股份有限公司及附属公司所有业务系统的变更管理，包括但不限于：
- 网络系统变更（配置调整、设备更换、拓扑变更）
- 系统配置变更（操作系统、中间件、数据库、应用系统）
- 网络调整与割接
- 防火墙策略变更

## 3. 职责分工

| 角色 | 职责 |
|------|------|
| 系统运维部 | 统筹负责网络调整和割接工作，协调技术方案和实施细则 |
| 信息安全部 | 变更安全评审、变更执行监督、安全测试 |
| 网络安全管理员 | 按变更流程处理安全相关问题 |
| 网络管理员 | 按流程处理网络故障、防火墙配置变更 |
| 部门领导 | 审批重大网络调整和割接方案 |

## 4. 管理要求

### 4.1 配置变更管理

- 所有配置变更需通过灵犀平台进行统一工单审批
- 需经过上级和运维的审批，禁止直接修改生产环境
- 配置变更人员需指定角色执行，遵循最小必要原则
- 变更实施需进行必要的安全测试

### 4.2 网络系统变更管理

网络系统遭到外部非法入侵破坏、存在重大安全隐患、重新规划网络结构、网络扩容、设备搬迁或因监管整改需要调整时，须按变更流程进行整体变更与跟进。

### 4.3 防火墙配置管理

#### 4.3.1 配置管理
- 网络管理员需及时对防火墙配置进行增加、修改或删除
- 除网络管理员及网络安全管理员外，任何人不得有权限对防火墙配置进行变更操作
- 若防火墙规则有更新，网络管理员需对规则更新有合理的解释或注释

#### 4.3.2 权限管理
- 除网络安全管理员、网络管理员外，任何人不得授有高权限对策略进行变更和删除
- 如遇紧急情况，需严格遵守内部权限管理要求，视情况临时调整

#### 4.3.3 测试管理
- 防火墙策略正式上线前需进行必要的安全测试
- 网络安全管理员须按照安全开发周期（SDL）相关流程进行测试

#### 4.3.4 升级管理
- 网络管理员须按时升级防火墙，包括安全策略配置、补丁
- 升级需在安全测试通过后上线

### 4.4 网络调整与割接

网络调整和割接工作由系统运维部统筹负责，需遵循以下要求：

- 所有重大网络调整和割接方案必须提前报部门领导审批，经批准后方可执行
- 必须事先进行严格的测试验证，确保网络安全
- 必须制定明确的技术方案，方案中须含有回退预案
- 申请批复后应及时召开工作会议，落实工作步骤和具体细节
- 执行前必须对系统准备情况进行现场检查
- 调整割接工作应安排在业务运行低谷时段（如夜晚）
- 工作完成后加强值班监控，密切注意系统运行情况

## 5. 技术要求

### 5.1 备份管理

- 网络设备配置每半年备份一次
- 备份位置至少需要放在文件服务器，重要及核心设备须有异地备份
- 对网络设备策略进行变更时，配置数据应及时备份
- 防火墙系统定期备份相关信息

### 5.2 日志与审计

- 网络设备的运行日志至少要保存半年
- 网络安全管理员需定期对网络配置的变更操作记录进行审计
- 需对用户及管理员的访问权限以及重要资源的控制策略进行检查

## 6. 检查与考核

- 网络管理员定期（至少每月一次）对网络设备、网管及配套设施进行巡视巡检
- 网络安全管理员定期对网络配置变更记录进行审计
- 若变更过程中出现违规操作，按公司安全管理规定进行处罚
