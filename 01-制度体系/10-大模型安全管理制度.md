# 大模型安全管理制度

## 1. 目的

规范大语言模型（LLM）研发、部署及应用全生命周期安全管理，确保其技术可控、数据合法、内容合规，防范数据泄露、算法偏见、技术滥用等风险。

**制定依据：**
- 《网络安全法》《数据安全法》《个人信息保护法》
- 《生成式人工智能服务管理暂行办法》
- 《人工智能生成合成内容标识管理办法》
- 《互联网信息服务深度合成管理规定》
- 《互联网信息服务算法推荐管理规定》

## 2. 适用范围

适用于奇富科技有限公司及附属公司涉及大模型研发、训练、部署、运营、使用及相关数据处理活动的所有部门及人员。

## 3. 管理职责

### 3.1 大模型安全委员会

由信息安全部、合规部、公共事务部、法务部、各业务线安全接口人组成，负责：
- 审批大模型处理活动的风险评估报告
- 收集、分析并确认大模型安全需求，监督安全措施执行情况
- 针对紧急大模型安全事件决策处置方案

### 3.2 各部门职责

| 部门 | 职责 |
|------|------|
| 信息安全部 | 数据安全评估、内容过滤机制建设、对抗性测试、安全监测与审计、算法备案/登记等 |
| 合规部 | 法律法规解读、数据合规评估、内容合规性评估、服务合规性评估、算法备案/登记等 |
| 法务部 | 知识产权管理、商业秘密保护、数据跨境流动评估、算力法律评估 |
| 公共事务部 | 与监管机构沟通、算法主体备案/登记等、监管事件处置 |
| 安全接口人 | 传达大模型安全要求、响应工作、协助制定安全标准 |

## 4. 数据安全管理

### 4.1 数据采集

- 所有训练数据必须来自合法、公开或经授权的来源
- 开源数据需具有开源许可协议或授权文件
- 自采数据需有采集记录且具有相应授权
- 商业数据需有交易合同、合作协议等，交易方需提供语料来源承诺
- 使用者输入信息作为语料时需具有使用者授权记录
- 建立数据来源追溯机制，明确禁止采集的数据类型

### 4.2 训练数据

- 应采取关键词、分类模型等方式过滤违法不良信息
- 根据数据敏感程度建立分级管控机制
- **禁止使用生产用户L4数据作为大模型训练数据**
- 标注规则需按法律法规、监管规定执行

### 4.3 数据存储

- 训练数据与用户交互数据分离存储
- 模型训练数据的版本需可追溯
- 核心数据加密存储，访问权限实施最小化原则
- 根据法规和业务需求定义存储时长，过期数据需彻底删除

## 5. 模型开发与部署安全

### 5.1 模型开发阶段

- 基于第三方基础模型提供服务应使用已经备案的基础模型
- 在需求分析阶段识别潜在威胁，将安全合规要求纳入项目开发文档
- 伦理审查：识别模型可能产生的社会伦理风险
- 算法公平性保障：引入定量公平性指标，减少输出偏见
- 代码安全管控：遵循安全编码规范
- 基础设施安全加固：使用专用环境，应用上线前需提交安全审计

### 5.2 模型评估阶段

- 对训练数据中的高风险样本进行全链路溯源审计
- 安全性测试：渗透测试、模糊测试，模拟Prompt注入、对抗样本攻击
- 性能与可靠性评估：建立性能监控指标体系
- 生成内容准确性：采取技术措施提高生成内容的质量

### 5.3 模型部署要求

- 部署环境与开发/测试环境严格隔离
- API接口须配置请求速率限制与智能流量过滤
- 容器化部署需确保仅运行经过签名验证的镜像
- 所有数据传输需强制加密
- 调用外部大模型场景需接入安全智盾进行安全性监测

## 6. 使用规范

### 6.1 禁止场景与服务

严禁将大模型应用于以下场景：
- 诈骗、伪造、暴力犯罪等违法活动
- 换脸换声、泄露隐私等侵害人格权
- 代写论文、考试作弊等破坏诚信行为
- 传播迷信色情仇恨等不良内容
- 扰乱市场竞争、误导投资或医疗判断
- 误导未成年人认知

### 6.2 用户管理

- 实行实名认证分级管理制度
- 对敏感操作强制触发二次验证
- 基于最小权限原则实施临时权限申请与权限自动回收
- 构建用户行为基线模型实时检测异常操作
- 限制账号登录设备数量，防范账号盗用

### 6.3 员工使用规范

- 严格按照公司各项保密制度使用和操作模型
- 确保输入内容合法合规，不得输入违法违规内容
- 生成内容需符合法律法规规定，避免侵犯知识产权
- 不得未经审批将模型输出结果直接对外公开使用或作为重要决策依据
- 自研大模型仅获授权的员工可基于工作需要访问

## 7. 大模型安全监测

- 对请求日志进行结构化存储，加密存储并保留至少6个月
- 内容审核机制需包括规则检测、AI分析及人工复核
- 建立分级关键词库（禁用词、高危词、观察词），保持动态更新

## 8. 应急管理

### 8.1 安全事件分级

| 级别 | 描述 |
|------|------|
| 一级 | 模型产生违法内容并大规模传播 |
| 二级 | 发生模型核心训练数据泄露 |
| 三级 | 模型生成内容标识缺失导致虚假信息扩散 |
| 四级 | 模型输出存在算法歧视引发投诉 |
| 五级 | 恶意用户发起对抗攻击导致模型功能异常 |

### 8.2 事件响应流程

- **一级事件：** 立即响应，即刻阻断模型服务，2小时内上报属地网信部门
- **二级事件：** 24小时内响应，冻结相关数据库访问权限，72小时内告知受影响用户
- **三级事件：** 72小时内响应，撤回未标识内容，修复标识模块
- **四级事件：** 七日内响应，模型回滚至无歧视版本
- **五级事件：** 对恶意IP实行流量拦截，48小时内部署对抗训练后新版本

## 9. 责任追究

根据《生成式人工智能服务管理暂行办法》等法规，采取"事件等级挂钩追责"机制：
- 一级事件：责任人记三级警告，纳入绩效评估
- 二级事件：责任人记二级警告，纳入绩效评估
- 三级及以下事件：限期3日内整改，责任人记一级警告
