# 数据安全管理制度

## 1. 目的

加强和规范奇富科技数据安全管理工作，指导员工快速对数据级别进行判定，明确数据生命周期内的安全管理要求。

## 2. 适用范围

- 主体范围：奇富科技股份有限公司及附属公司
- 生命周期范围：数据产生、存储、使用、传输、销毁、归集等全生命周期
- 数据形式：纸质形式与电子形式的数据

## 3. 职责分工

| 部门 | 职责 |
|------|------|
| 信息安全部 | 制度制定、风险评估、安全培训、安全事件响应、安全审计、数据分类分级落实、安全策略设定与审计 |
| 合规部 | 协同建立数据安全风险专项小组，提供法律支持，保障内部制度合规运行 |
| 公共事务部/公关部 | 建设监管沟通生态，推动安全认证工作，落地监管部门工作要求 |
| 系统运维部 | 身份识别与鉴别、角色权限管理、账号管理、接口安全控制、日志审计 |
| 产品系统技术部 | 安全需求实现、开发人员管理（包括外包人员） |
| 其他各部门 | 数据资产分类定级、数据使用规则定义、权限规范 |

## 4. 数据分类分级管理

### 4.1 数据分类分级策略

公司内部应对数据进行分类与安全定级，暂未识别到"数据资产分类分级清单"中的数据默认按照安全级别最高级别处理。

数据等级标识分为：

| 数据级别 | 重要程度 | 影响程度 |
|----------|----------|----------|
| L5 | 极高 | 严重 |
| L4 | 极高 | 严重 |
| L3 | 高 | 中等 |
| L2 | 中 | 轻微 |
| L1 | 低 | 忽略 |

### 4.2 L5核心数据处理
- 涉及核心数据的处理活动，应实施公司最高等级的管控措施
- 内部若无上级主管单位或监管方授权，无权查看、使用任何L5级别数据

### 4.3 L4绝密数据处理
- 原则上严禁对外传播、提供
- 如因业务需要，需由高层级别领导邮件审批通过后方可允许
- 需通过工单申请，业务、合规、安全三方评估审批
- 原则上不允许员工在系统中直接查询或以其他方式获取L4级数据

### 4.4 L3机密数据处理
- 对外提供需以邮件、信息安全平台、资信平台提出申请
- 需与接收方签署《保密协议》

## 5. 数据生命周期管理

### 5.1 数据产生
- 遵循最小化收集原则，仅收集业务必需的最少数据
- 收集数据前应与数据被收集方明确双方的安全责任和义务
- 通过已授权的人员或程序完成，禁止未授权数据产生行为

### 5.2 数据存储
- L3级及以上数据必须加密存储
- L4级数据不允许在无权限控制的库表中存储
- 操作系统管理员、数据库管理员、业务系统管理员应做到职责分离、账号分离
- 备份数据的保护要求不低于源数据的保护要求

### 5.3 数据使用
- 敏感数据脱敏显示
- 禁止用户在应用系统前端批量导出敏感数据
- L4级数据使用需通过工单申请
- 访问数据所使用的终端设备必须符合网络准入要求
- 远程访问数据时应使用公司统一要求的VPN加密通道

### 5.4 数据传输
- 跨安全域之间的数据访问需明确定义控制策略
- L3级及以上数据传输应进行加密与完整性保护
- 数据跨境传输需进行风险评估

### 5.5 数据销毁
- 交易类数据保留期限：至少5年
- 用户数据（非交易类）保留期限：至少2年，到期后需去标识化处理
- 生产数据使用完成后应及时清除
- 介质离开安全区域前应清理数据确保不可恢复

### 5.6 数据归集
- 归集前需进行去标识化处理
- 涉及多个安全级别的数据混合使用时，保护等级取最高级别

## 6. 数据安全运营管理

### 6.1 数据访问权限管理
- 遵循最小授权原则
- 审批要求和操作流程应覆盖数据访问账号的分配、开通、使用、变更、销毁环节

### 6.2 数据提数管理
- 提取数据需按流程申请审批
- 未按数据级别使用和对外提供的，信息安全小组有权处罚

### 6.3 数据安全评估
- 内部外部数据合作需求均需提交信息安全部进行安全审核
- 数据外传、数据交互等场景需进行安全风险评估
- 已开展合作的内外部合作如经审计发现风险较高的，需做安全整改

### 6.4 数据安全审计
- 信息安全部定期或不定期对内部各中心、各业务进行数据安全审计

### 6.5 数据安全培训
- 每季度举办1-2场数据安全培训

### 6.6 重要数据安全管理
- 信息安全部应按照监管部门要求，定期对重要数据进行备案和安全风险评估

## 7. 合作方管理

### 7.1 合作方安全评估
- 接收大量用户信息的合作方需签署保密协议
- 第三方系统接入需由信息安全部进行安全评估
- 评估内容包括：安全合规性、数据传输方式、最小必要原则、访问控制、接口安全、加密/脱敏方案

### 7.2 接口安全要求
- 需实现四点安全保障：接口认证、用户权限控制、参数加密、网络传输加密

### 7.3 合作方安全事件定级

| 级别 | 描述 |
|------|------|
| 一级（特大） | 真实数据泄露，对用户造成严重影响或舆论影响或监管处罚 |
| 二级（重大） | 真实数据泄露，对用户造成财产损失 |
| 三级（较大） | 真实数据泄露，泄露量级较大 |
| 四级（一般） | 真实数据泄露，数据量较小，影响轻微 |

### 7.4 合作方安全事件追责

追责机制包括：内部排查、临时停止合作、合作方风险排查及整改、经济赔偿、终止合作关系等。
