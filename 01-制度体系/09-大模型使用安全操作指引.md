# 大模型使用安全操作指引

## 1. 目的

规范员工在研发、运维、办公及业务场景中安全、合规使用 AI 大模型服务，防范数据泄露、敏感信息外发、越权访问、接口滥用、模型输出误用及数据出境等风险。

**制定依据：**
- 《个人信息保护法》《数据安全法》《网络安全法》
- 《数据出境安全评估办法》《数据出境安全评估申报指南（第三版）》
- 《促进和规范数据跨境流动规定》
- 个人信息、敏感个人信息、金融数据安全相关国家标准和行业标准
- 公司数据安全管理、个人信息保护、数据分类分级等相关制度

## 2. 适用范围

- **人员范围：** 全体员工
- **行为范围：** 在工作过程中使用各类 AI 大模型服务的行为，包括奇富自有 AI、可信源 AI、境内外部 AI、境外外部 AI
- **数据范围：** 通过 AI 接入或调用公司知识库、代码库、日志库、数据库、工单系统、报表系统等数据源的场景
- **使用前提：** 员工使用 AI 服务前，应确认所使用的 AI 服务已纳入公司准入范围，并根据公司数据分类分级要求判断数据等级和敏感程度
- **禁止行为：** 未经公司批准，不得私自注册、购买、接入或使用外部 AI 服务处理公司数据或公司工作内容；严禁将公司接入的 AI 大模型服务用于私人用途

## 3. 基本原则

员工使用 AI 服务应遵循以下原则：

| 原则 | 说明 |
|------|------|
| 先准入、后使用 | 仅使用已纳入公司准入范围的 AI 服务 |
| 先分级、后输入 | 先判断数据等级和敏感程度，再决定可否输入 |
| 最小必要 | 向 AI 提交内容应限于完成任务所必需的最小范围 |
| 脱敏优先 | 能使用公开信息、虚构样例、Mock 数据、伪代码、脱敏数据或聚合数据的，不得使用真实数据 |
| 境外从严 | 境外 AI 服务须遵循更严格的数据处理要求 |
| 出境合规 | 涉及数据出境的，应先完成合规评估与审批 |
| 统一通道、留痕可审 | 通过公司统一平台接入，全流程日志记录 |
| 输出复核、责任明确 | AI 输出须经人工审查确认，员工对使用结果负最终责任 |

> 对 AI 服务来源、数据等级、可输入范围、审批要求、是否涉及境外处理存在不确定的，应暂停使用，并先行咨询信息安全、法务或合规部门。

## 4. 模型分类分级

根据模型部署位置、数据流向和风险等级，将 AI 服务分为四个等级：

### 4.1 M1 — 奇富自有 AI（低风险）

- **定义：** AI 部署在公司自己的机房/自有服务器，不连外网也能用
- **适用定位：** 公司内部优先使用的 AI 类型，适用于办公辅助、研发辅助及较高安全要求的内部数据处理
- **风险等级：** 低风险 ⭐⭐⭐⭐⭐（推荐）
- **主要风险：** 内部权限越权、知识库污染、未授权数据接入、提示词泄露、输出误用、模型幻觉导致错误决策
- **禁止行为：**
  - 超出系统获准范围输入数据
  - 将未授权数据源、知识库、代码库、生产日志接入 AI
  - 绕过权限访问或提问他人知悉的数据
  - 将 AI 输出直接作为生产变更、对客答复、风控判断等最终依据

### 4.2 M2 — 可信源 AI（中低风险）

- **定义：** AI 部署在与公司内网相通的可信私有云环境中
- **适用定位：** 公司级/业务级推荐使用的 AI 类型，适用于需要安全隔离、统一管理的办公、研发、运营、合规等场景
- **风险等级：** 中低风险 ⭐⭐⭐⭐
- **主要风险：** 云厂商运维访问、租户配置不当、权限继承错误、日志留存不足、跨环境联通、第三方插件接入
- **禁止行为：**
  - 将私有云 AI 与未经批准的外部模型、插件、API 或第三方服务联通
  - 超出准入范围输入数据
  - 未经审批接入客户数据、生产日志、核心业务规则、代码库、接口文档等敏感数据
  - 绕过权限和审计机制使用

### 4.3 M3 — 境内外部 AI（中高风险）

- **定义：** 境内公有云 AI/API、境内模型官网、境内 SaaS 内嵌 AI 功能。例如：通义千问、文心一言、豆包、Kimi、DeepSeek 境内服务、已准入的 WPS AI/钉钉 AI/飞书 AI 等
- **适用定位：** 可控使用的外部 AI 类型，适用于公开信息、低敏办公内容、脱敏数据、通用技术问题、一般文本处理和通用研发辅助
- **风险等级：** 中高风险 ⭐⭐
- **主要风险：** 数据提交至外部服务商、供应商留存或训练使用、日志不可完全掌控、SaaS 权限继承、接口密钥泄露、未审批 API 私接
- **禁止行为：**
  - 输入客户个人信息、敏感个人信息、交易数据、账户数据、生产日志、源代码密钥、Token、证书、数据库连接串、核心业务规则
  - 使用个人账号处理公司数据
  - 私自调用未经批准的 API

### 4.4 M4 — 境外外部 AI（高风险）

- **定义：** 境外公有云 AI/API、境外模型官网、境外 SaaS 内嵌 AI 功能。例如：ChatGPT、OpenAI API、Gemini、Claude、GitHub Copilot、Notion AI 等
- **适用定位：** 从严限制使用，原则上仅适用于公开信息、通用问题咨询、低风险文本处理、示例代码或伪代码
- **风险等级：** 高风险 ⭐
- **主要风险：** 数据出境、境外供应商留存与训练使用、监管不可控、账号不可控、插件链路不透明、商业秘密或个人信息泄露
- **禁止行为：**
  - 输入国家秘密
  - 输入任何公司非公开数据（核心数据、重要数据等）
  - 输入客户信息、个人信息、敏感个人信息、金融交易数据、账户数据、生产日志、源代码、密钥、系统架构、业务规则、合同、会议纪要、内部报表等
  - 使用个人账号、代理工具、插件或未经批准的 API 处理公司工作内容

## 5. 境外 AI 服务特别要求

- 境外 AI 服务原则上仅限处理互联网公开信息、通用问题咨询和低风险文本内容
- **原则上禁止使用境外 AI 服务处理以下数据：**
  - 国家秘密、核心数据、重要数据
  - 个人信息、敏感个人信息、客户个人信息
  - 金融账户数据、交易流水数据、征信/授信数据、支付清算数据
  - 核心风控规则、生产系统日志、源代码密钥
  - 其他受监管的高敏感数据
- **例外处理流程：** 确因业务必要涉及上述数据或可能构成数据出境的，应按照"先评估、后审批、再使用"原则，完成业务必要性论证、数据分类分级、个人信息保护影响评估、数据出境合规评估、技术保护措施验证和公司专项审批等流程
- **数据出境安全评估：** 符合数据出境安全评估适用情形的，应依据《数据出境安全评估申报指南（第三版）》等规定申报
- 未完成数据出境合规判断、专项审批和必要的安全评估前，任何部门或个人不得将上述数据输入、上传、同步、接入或通过 API 提交至境外 AI 服务

## 6. 各场景安全操作要求

### 6.1 研发运维场景

#### 6.1.1 编码架构实现

| 维度 | 要求 |
|------|------|
| 可选模型 | M1/M2；M3/M4 限通用编程 |
| 输入安全 | 🚫 严禁输入凭证：明文密码、Token、API Key、AK/SK 密钥、SSL 证书、JWT 字符串；🚫 严禁输入真实基础设施信息：生产环境真实内网 IP、内部域名、机房拓扑图；🚫 严禁输入客户隐私：未经脱敏的真实客户姓名、手机号、身份证号、银行卡号；🚫 禁止输入违法违规内容；🚫 严禁未经授权将受保护的公司专有算法或商业秘密作为训练数据或提示词输入；✅ 使用前需明确数据限定为我方数据，对合作机构同步的保密信息、委托处理的信息应避免使用 |
| 数据调用 | 🚫 严禁输入完整业务源码、核心算法逻辑、账号密钥、配置秘钥；🚫 代码、架构方案仅脱敏后片段提问，禁止上传完整工程包、生产环境真实数据库建表语句或全盘系统架构图；🚫 不向外部大模型透露内网拓扑、核心业务架构、未立项规划；✅ 在要求 AI 补全或检查代码时，必须对带有强业务特征的变量名/函数名进行泛化 |
| 输出安全 | 🚫 禁止盲目信任并直接复制运行大模型生成的代码、SQL、脚本或配置指令；✅ 必须遵循"人工审查兜底"原则；✅ 涉及生成内容对外发布使用的，需添加水印标识 |
| 安全审批 | 涉及公司代码、代码审查、测试、代码解释、架构设计、接口文档、数据库设计、核心业务逻辑等，优先选择 M1、M2。如仅咨询通用编程语法、开源框架用法、示例代码，可使用已准入的 M3、M4 |

|------|------|
| 可选模型 | M1/M2；M3/M4 限通用测试/脱敏材料 |
| 输入安全 | 🚫 技术方案、接口文档禁止夹带真实库表结构、涉密业务规则；🚫 内部未公开技术资料、评审纪要不直接投喂公有大模型 |
| 输出安全 | ✅ 大模型生成文档需脱敏涉密信息，留存版本审计痕迹 |

#### 6.1.3 运维故障应急

| 维度 | 要求 |
|------|------|
| 可选模型 | M1/M2；M3/M4 限通用排障 |
| 输入安全 | 🚫 严禁将服务器直接导出的原始报错日志不加查看地整段复制粘贴给 AI；🚫 不泄露生产部署架构、容灾拓扑、中间件真实账号权限；✅ 报错日志传输前必须人工或通过脚本清洗掉敏感信息，只保留代码报错逻辑堆栈 |
| 输出安全 | 🚫 禁止直接以 root 或管理员最高权限盲目执行大模型提供的未知排障脚本、批处理命令或系统配置修改指令；✅ 运维人员必须审查 AI 提供的运维指令 |

#### 6.1.4 安全工程效能

| 维度 | 要求 |
|------|------|
| 可选模型 | M1/M2；M3/M4 限通用安全知识 |
| 输入安全 | 🚫 严禁上传 CI/CD、容器编排配置中的私密镜像地址、仓库凭证；🚫 代码安全审计仅用脱敏样本，不上传涉密漏洞详情；🚫 数据脱敏、权限方案设计不得带出核心合规策略与涉密规则 |
| 输出安全 | ✅ 自动化脚本、流水线配置生成后，使用人需做密钥、权限安全审查 |

### 6.2 业务运营场景

#### 6.2.1 产品风控服务

| 维度 | 要求 |
|------|------|
| 可选模型 | M1/M2；M3/M4 限公开政策/通用方法 |
| 数据调用 | 🚫 严禁将公司内部未公开的公文、员工简历、商务合同、财务报表等直接粘贴或上传至外部 AI；🚫 禁止员工使用个人手机号、个人邮箱私自注册外部未经安全审查的 SaaS 办公类大模型产品；🚫 禁止使用境外 AI；✅ 优先使用本地化部署 AI 服务；✅ 定期清理对话记录；✅ 统一内部办公入口 |
| 输入安全 | 🚫 严禁输入办公类凭据：VPN 账号、邮箱密码、内部协同软件 Token、系统登录凭证；🚫 禁止直接投喂原件：未经删减/脱敏的长篇内部邮件、内部沟通截图、未公开的系统导出表格；🚫 禁止输入违法违规内容；✅ 强制脱敏与占位符原则：核心人物、具体金额、联系方式必须泛化 |
| 数据调用 | 🚫 绝对禁止将风控规则逻辑、反欺诈策略模型、黑灰产拦截阈值及规则代码提供给外部 AI；🚫 严禁输入包含真实用户风控画像的运营清单；✅ 运营活动策划只能使用高度抽象的业务场景描述 |
| 输出安全 | 🚫 禁止盲目发布与应用：未经人工核对的事实与数据不得直接对外发布、群发邮件、官方决策或业务审批；🚫 禁止私自绕过公司网络监控外发运营数据；✅ 强制人工审查兜底 |

| 输出安全 | 🚫 AI 仅辅助报表整理、流程文案、手册编撰，所有数据类输出需人工审查脱敏；✅ 生成后需人工审查，确保计算与汇总逻辑 100% 准确 |

| 可选模型 | M1/M2；M3/M4 限公开通用任务 |
| 输入安全 | 🚫 严禁输入人事隐私、内部组织架构涉密信息；🚫 严禁上传包含员工或候选人真实 PII 隐私的原始简历文件；🚫 严禁输入包含员工真实薪酬流水、绩效评级、期权分配及敏感人事变动的表格；✅ 仅可用于通用公开办公问题解答；✅ 提取简历亮点前必须先删除/模糊化候选人身份标识 |
| 输出安全 | 🚫 绝对禁止直接使用大模型输出内容作为正式决策依据；🚫 严禁将大模型提供的劳动法合规建议直接作为人事处理的最终法定依据；✅ 候选人面试评价、简历总结仅限辅助参考，最终决策须由人工做出 |

## 7. 通用安全红线

### 7.1 绝对禁止的行为

- 🚫 严禁使用公有 SaaS 网页版处理公司代码、数据
- 🚫 严禁跨网络环境调用：测试环境或开发网的 AI 工具绝不允许跨网段访问生产环境的大模型接口或生产数据
- 🚫 禁止使用境外 AI 服务处理公司重要数据、个人信息
- 🚫 禁止将未经公司批准的数据源接入 AI（个人网盘、个人邮箱、个人代码仓库等）
- 🚫 禁止 AI 超出批准范围调用数据，禁止为方便使用开放全量数据库、全量日志
- 🚫 禁止将公司内部知识库、代码库、日志库、数据库等直接接入未经批准的外部 AI、境外 AI、插件或第三方代理平台
- 🚫 禁止绕过公司统一身份认证、访问控制、数据权限、审批流程或审计机制调用数据
- 🚫 禁止 AI 未经审批进行批量读取、批量导出、批量下载、批量总结敏感数据
- 🚫 禁止关闭、删除、篡改或绕过数据调用日志、审计日志和安全监控
- 🚫 禁止私自绕过公司网络监控，通过未授权的隐蔽网络通道（私自挂载外部代理、连接个人手机热点等）向外部大模型外发数据
- 🚫 禁止使用未经授权的第三方专利方法生成内容，不得侵犯他人知识产权
- 🚫 禁止使用大模型用于非工作场景，严禁生成违法违规内容

### 7.2 必须遵守的要求

- ✅ 优先使用本地化部署的 AI 服务
- ✅ 定期清理对话记录，避免累积敏感信息
- ✅ 所有需要系统级对接、业务调用外部大模型能力，须通过统一平台进行准入、统一鉴权与日志留痕
- ✅ 可在公司批准范围内，将 AI 接入已完成安全评估的数据源
- ✅ 接入前应确认数据源负责人、数据等级、使用目的、访问范围、用户权限、调用频率、日志审计要求
- ✅ 涉及个人信息、客户信息、交易信息等内容时，应优先使用脱敏、去标识化、样例化数据
- ✅ 数据调用应记录调用人、调用时间、调用数据源等信息
- ✅ 发现 AI 异常调用、越权访问、批量查询、敏感数据返回等情况，应及时暂停调用并上报安全部门
- ✅ 所有 AI 输出在落地到实际业务或主干分支前，必须经过人工审查与逻辑确认
- ✅ 涉及生成内容对外发布使用的，需按照国家监管要求添加相应水印标识

## 8. 数据安全与隐私保护

### 8.1 重要数据保护

公司重要数据范围包括但不限于：用户敏感个人信息（10万以上敏感个人信息）等。详见《电信领域重要数据识别指南》及相关数据分类分级规范。

### 8.2 个人信息保护

参考 GB/T 35273-2020、GB/T 43697-2024、GB/T 45574-2025，个人信息及敏感个人信息涵盖：
- 个人基本资料、身份信息、生物识别信息、网络身份标识信息
- 健康/医疗健康信息、个人教育/工作信息
- 金融账户信息、个人交易信息、个人资产信息、个人借贷信息
- 身份鉴别信息、个人通信信息、联系人信息
- 个人操作记录、业务行为数据、设备识别码
- 位置信息、行踪轨迹信息、住宿出行信息
- 个人标签信息、个人运动信息等

### 8.3 数据出境合规

涉及数据出境的行为，应参照《数据出境安全评估申报指南（第三版）》进行处理，具体包括：
- 数据出境行为识别
- 适用情形判断
- 申报条件确认
- 办理流程执行

## 9. 违规处理

对于未通过大模型网关平台申请的私自使用行为，员工应严格遵守公司大模型安全管理、数据安全及员工管理手册等安全制度要求。相关违规行为一经发现，将按照公司安全制度进行处理。
