# 数据分类分级管理制度

## 1. 目的

确保公司敏感数据、关键数据和受到法律保护的数据得到相应级别的保护，降低发生数据泄露或其他类型网络攻击的可能性，提高数据使用合规性，推动数据安全相关法律法规落地。

## 2. 适用范围

适用于奇富科技股份有限公司及附属公司涉及到的所有信息数据的分类分级管理。

## 3. 数据分类

### 3.1 分类原则

| 原则 | 说明 |
|------|------|
| 科学性原则 | 按照互联网金融行业数据的多维特征及逻辑关联进行科学系统化分类 |
| 稳定性原则 | 选择分类对象最稳定的本质特性作为数据分类的基础和依据 |
| 实用性原则 | 确保每个类目下要有数据，数据类目划分符合用户普遍认识 |
| 扩展性原则 | 具有概括性和包容性，能实现各种类型数据的分类，满足将来可能出现的数据类型 |

### 3.2 数据类别

按照数据分类原则并结合公司实际运营情况，将数据分为：
- **用户数据：** 公民个人信息类，可参考国内相关标准进行分类
- **业务数据：** 业务运营过程中产生的数据
- **公司数据：** 公司经营相关的数据

## 4. 数据分级

### 4.1 数据等级标识

| 影响程度 | 数据重要程度 | 数据级别 |
|----------|-------------|----------|
| 严重 | 极高 | L5、L4 |
| 中等 | 高 | L3 |
| 轻微 | 中 | L2 |
| 忽略 | 低 | L1 |

### 4.2 影响程度分类

| 影响程度 | 参考说明 |
|----------|----------|
| 严重 | 可能导致公司遭遇破产、关停等风险；可能引发公众广泛诉讼或集体诉讼甚至群体性事件；可能导致监管部门严重处罚 |
| 中等 | 可能使得公司遭遇法律、大量资产损失等风险；可能引发一定数量用户对本机构诉讼；可能导致监管部门较严重处罚（包括暂停经营资格等） |
| 轻微 | 可能导致公司遭遇运营困难、轻微资产损失等风险；可能导致监管部门轻微处罚（罚款、公开批评等）；可能对本机构声誉造成一定程度损害 |
| 忽略 | 造成的影响极其轻微，可忽略不计 |

## 5. 数据分级处理规范

### 5.1 L5 核心数据

- 内部若无上级主管单位或监管方授权，无权查看、使用任何L5级别数据
- 完全遵照并执行《中华人民共和国数据安全法》等相关安全条例中对国家级数据的各项要求

### 5.2 L4 绝密数据

- 原则上严禁对外传播、提供
- 私自将绝密数据带出公司使用的，视为泄露公司内部信息，将严肃处理
- 如因业务需要对外提供或带出使用，需由高层级别领导邮件审批通过
- 需通过工单申请，业务、合规、安全三方评估审批通过后方可使用
- 原则上不允许员工在业务、数据平台或其他系统中直接查询L4级数据
- 如需加工处理，需在加密、脱敏处理后，将目标数据安全等级降级至L1~L3后方可使用

### 5.3 L3 机密数据

- 对外提供需通过邮件、信息安全平台、资信平台提出申请
- 按照审批流程审批后加密提供，不得提供任何明文数据
- 需与接收方签署《保密协议》，列明保护措施及责任承担

### 5.4 L2 秘密数据

- 所在部门的数据，对其他部门不可见
- 向其他部门或外部人员提供时需经部门领导、信息安全部邮件审批

### 5.5 L1 内部公开数据

- 在公司内部公开，对外保密
- 向外扩散有可能对公司利益造成损害
- 如需对外提供，需通过信息安全组审核

## 6. 附则

- 暂未识别到"数据资产分类分级清单"中的数据默认按照安全级别最高级别处理
