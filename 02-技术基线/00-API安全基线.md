# API安全基线

## 1. 概述

定义公司所有API接口必须满足的安全设计要求，确保接口访问安全、数据交换安全和传输安全。

## 2. 四大基本安全要求

第三方接口以及对接规范需实现以下四点以保证网络和数据安全：

| 序号 | 要求 | 说明 |
|------|------|------|
| 1 | 接口认证 | 所有第三方接口必须进行身份认证 |
| 2 | 用户权限控制 | 接口访问遵循最小权限原则 |
| 3 | 参数加密 | 敏感参数必须加密传输 |
| 4 | 网络传输加密 | 使用HTTPS等加密通道 |

如因业务方原因无法实现，需由业务方提供加密方案，由信息安全管理小组审核通过后方可接入。

## 3. 接口安全设计要求

| 序号 | 要求 | 风险等级 |
|------|------|----------|
| 1 | 接口应采用认证及加密技术 | 高 |
| 2 | 所有接口请求和响应、操作行为写入日志 | 高 |
| 3 | 接口访问进行身份认证和鉴权 | 高 |
| 4 | 明确每类接口的使用安全限制并进行管控 | 高 |
| 5 | 接口安全审计，确保符合法律法规及协议规定的安全规范 | 中 |
| 6 | 对API调用配置请求速率限制 | 中 |
| 7 | 禁止API返回敏感信息明文（如密码、密钥、身份证号等） | 高 |

## 4. 第三方系统接入管理

### 4.1 接入审批流程
- 第三方系统接入需由业务部门上报信息安全部进行安全评估
- 信息安全部基于安全管理制度体系和技术防护手段进行综合评估
- 合作方需提供安全资质证明材料：渗透测试报告、等保测评报告、ISO27001证书等

### 4.2 评估内容
| 评估维度 | 评估内容 |
|----------|----------|
| 安全合规性 | 合作方安全资质、合规证书 |
| 数据传输方式 | 传输加密、协议安全 |
| 最小必要原则 | 数据交换范围是否遵循最小必要 |
| 访问控制措施 | 身份认证、权限管理 |
| 接口安全 | 认证、加密、防攻击 |
| 加密/脱敏方案 | 数据保护技术措施 |

## 5. API数据调用规范

### 5.1 禁止行为
- 🚫 禁止将未经批准的数据源接入API
- 🚫 禁止API超出批准范围调用数据
- 🚫 禁止为方便使用开放全量数据库、全量日志、全量代码库
- 🚫 禁止绕过公司统一身份认证、访问控制、数据权限、审批流程或审计机制调用数据
- 🚫 禁止API未经审批进行批量读取、批量导出、批量下载、批量总结敏感数据
- 🚫 禁止关闭、删除、篡改或绕过数据调用日志、审计日志和安全监控

### 5.2 必要要求
- ✅ 接入前确认数据源负责人、数据等级、使用目的、访问范围等
- ✅ 数据调用应记录调用人、调用时间、调用数据源
- ✅ 发现异常调用、越权访问等情况应及时暂停调用并上报安全部门
- ✅ 涉及个人信息时应优先使用脱敏、去标识化、样例化数据
