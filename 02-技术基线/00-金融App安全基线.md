# 金融App安全基线

## 1. 概述

定义公司金融类App在开发和运营过程中必须满足的安全设计要求，覆盖从上线前备案到日常运营全流程。

## 2. 上线前合规要求

| 序号 | 要求 | 检查方式 |
|------|------|----------|
| 1 | 取得业务相关的经营许可证，业务范围与核准经营范围一致 | 证照核查 |
| 2 | 办理网络安全等级保护定级、备案和定期测评 | 等保证书 |
| 3 | 办理工信部ICP备案 | 备案证明 |
| 4 | 办理APP系统公安备案 | 备案证明 |
| 5 | 上线前参照《个人信息保护影响评估规范》开展合规评估 | 评估报告 |

## 3. 隐私合规要求

| 序号 | 要求 | 风险等级 |
|------|------|----------|
| 1 | 制定《隐私政策》《个人信息处理规则》，在首次安装/运行/注册/登录前公示并经用户同意 | 高 |
| 2 | 隐私政策在APP内易于访问，点击次数不超过4次 | 中 |
| 3 | 遵从应用商店隐私保护指引及个人信息保护有关规定 | 中 |
| 4 | 各应用商店及APP内部展示的个人信息处理规则版本一致 | 高 |
| 5 | 个人信息处理规则更新时应通知用户，重大变更需再次征得同意 | 高 |
| 6 | 各应用商店渠道同步更新 | 高 |
| 7 | 同步告知申请打开权限和要求提供个人敏感信息的目的 | 高 |
| 8 | 在对应业务功能启动时动态申请所需权限，不得一揽子强制授权 | 高 |
| 9 | 未经用户同意不得更改用户设置的权限状态 | 高 |
| 10 | 在非服务所必需或无合理场景下不得自启动或关联启动其他App | 中 |

## 4. 数据安全要求

| 序号 | 要求 | 风险等级 |
|------|------|----------|
| 1 | 实际收集的个人信息不得超出用户授权范围和期限 | 高 |
| 2 | 提供用户撤回同意收集个人信息的便捷途径 | 高 |
| 3 | 收集使用个人信息应遵循最小必要原则 | 高 |
| 4 | 用户可拒绝收集非必要信息或关闭非必要权限 | 高 |
| 5 | 用户明确不同意收集后不得频繁征求同意、干扰正常使用 | 中 |
| 6 | 提供删除或更正个人信息的渠道 | 高 |
| 7 | 依法设置双清单：个人信息清单和共享个人信息清单 | 高 |
| 8 | App停止运营后及时删除各应用商店版本并依法处理数据 | 高 |
| 9 | 金融机构核心环节在金融机构系统完成 | 高 |
| 10 | 不以人脸、指纹等生物特征作为唯一的个人身份认证方式 | 高 |

## 5. SDK管理要求

| 序号 | 要求 | 风险等级 |
|------|------|----------|
| 1 | 上线前检测SDK安全性，原则上不应允许热更新 | 高 |
| 2 | 使用第三方SDK应明示服务商名称、功能、个人信息处理规则 | 高 |
| 3 | 与第三方签署个人信息处理协议，明确双方权利义务 | 高 |
| 4 | 独立SDK功能模块应提供关闭/退出选项 | 中 |
| 5 | 发现安全隐患或被通报的SDK应及时移除 | 高 |

## 6. 自查管理

- 定期对App进行自查，参照《App违法违规收集使用个人信息行为认定方法》
- 对自查发现的问题及时整改
- 形成自查记录并留存
